# AIGC 热点雷达

每天早上 9 点把过去 24 小时的 AIGC 热点发到邮箱，并提供一个可按 **24 小时 / 3 天 / 7 天 / 30 天** 查询的网页。**每一条都附 AI 写的「为什么能火」的分析。**

**网页**：打开先看最上面的「3 分钟速览」；选题和视频旁边点「☆ 待做」加进右下角的待做清单，可以一键复制成选题单；标签看不懂就点一下，或者看页头「怎么看这份报告」。网页数据按板块分开加载，首屏只下几十 KB。

**往期**：网页页头「往期日报」或时间范围里的「往期」，可以选最近 30 天的任意一天，整个网页（选题、抖音 / B站 / 小红书热点、热梗热搜、热歌、AI 大事件）切换成那天最后一次扫描时的数据；选题区的「早报原文」是当天邮件的原样（另外带上了选题封面，邮件里不放封面）。

邮件和网页按这个顺序：

| # | 板块 | 内容 |
|---|---|---|
| 1 | 今日选题 | 抖音 10 个、B站 10 个。每个选题：时间段、作品 / 教程测评、单条 / 系列、难度和耗时、**时效**（刚起势 / 高峰期 / 已饱和，附依据）、为什么能火、怎么做、**工作流程**（只写步骤，不点名具体平台 / 模型）、**可复用公式 + 换皮方向**、**风险提示**、参考作品（也会借鉴小红书的 AIGC 爆款，主要依据可以是小红书作品）。下面是**跨平台信息差**（抖音爆了 B站还没人做，反之亦然）和**选题复盘**（前几天的选题后来又涨了多少，哪类信号更靠谱） |
| 2 | 抖音热点 | 高赞榜 TOP10（近 30 天严格按累计点赞）、**低粉爆款**（抖音粉丝不到 5 万、点赞过 10 万；B站粉丝不到 3 万、播放过 30 万）、24 小时飙升 |
| 3 | B站热点 | 同上，按播放 |
| 4 | 小红书热点 | 同抖音，按累计点赞，另外带阅读量；低粉爆款 = 粉丝不到 1 万、点赞过 5 万；每天早上更新一次 |
| 5 | 热梗热搜 | 抖音 / B站 / 微博热搜、小红书热点、抖音挑战、热梗精选，每条写为什么上热搜和 AI 做法 |
| 6 | 热歌飙升 | **AIGC 爆款常用 BGM**、四个平台的热歌榜 / 飙升榜，每首写为什么火、适合做什么 AI 二创 |
| 7 | AI 大事件 | **爆款工具榜**（近 7 天 AIGC 爆款里提到各工具的作品数，和上 7 天比）、AI 圈大事件 |

每条视频还会标**数据画像**：低粉爆款、分享率高（社交货币）、收藏率高（干货）、评论多 / 弹幕多（互动强）、点赞率高，以及时长和 BGM。

**限制：**
- 小红书自己的接口要登录 + 签名，免费拿不到，走的是 TikHub 付费接口（见下），每天只更新一次。
- 工具榜只统计标题 / 话题 / 简介里写了工具名的作品，大多数作品不写，看相对热度。
- 信息差是「我们抓到的数据里没找到同题材」，不代表另一个平台完全没有。
- AI 分析里标「推测」的，是 AI 根据有限信息做的判断。

## 运行方式

全部跑在 GitHub 上，不需要自己的电脑开机：

- **每天北京时间 08:20**：采集 → AI 标注 → AI 日报 → 更新网页 → 等到 **09:00** 发邮件
- **其余每 3 小时**：采集 → AI 标注 → 更新网页
- 数据存在仓库的 `data` 分支，保留 40 天
- 每天的 DeepSeek 费用大约几分钱

## 第一次部署

1. **建仓库**：在 GitHub 新建一个 **Public（公开）** 仓库（免费账号的 GitHub Pages 只支持公开仓库），把代码推上去。
2. **开网页**：仓库 → Settings → Pages → Build and deployment → Source 选 **GitHub Actions**。
3. **填密钥**：仓库 → Settings → Secrets and variables → Actions → New repository secret，逐个添加：

   | 名称 | 填什么 |
   |---|---|
   | `DEEPSEEK_API_KEY` | DeepSeek 的 API Key |
   | `SMTP_USER` | 发信用的 QQ 邮箱，如 `123456@qq.com` |
   | `SMTP_PASS` | QQ 邮箱的 **SMTP 授权码**（不是 QQ 密码，见下方） |
   | `MAIL_TO` | 收件人，多个用英文逗号隔开 |
   | `SMTP_HOST` / `SMTP_PORT` | 可选，不用 QQ 邮箱时才填（163 邮箱：`smtp.163.com` / `465`） |

4. **试跑**：仓库 → Actions → 左侧「AIGC 热点雷达」→ Run workflow → 模式选 `daily-now` → 运行。大约 3–5 分钟后会收到第一封邮件，网页地址是 `https://你的用户名.github.io/仓库名/`。

### QQ 邮箱授权码怎么拿

QQ 邮箱网页版 → 设置 → 账号与安全 → 安全设置 → 开启「POP3/IMAP/SMTP 服务」→ 按提示用手机验证 → 得到一串 16 位授权码。

### 让推送出现在微信里

收件人用 QQ 邮箱，然后在微信里搜索并开启「QQ邮箱提醒」，邮件到达时微信会弹通知。

## 抖音高赞 AIGC（TikHub，付费）

抖音的搜索、话题、热门榜都要登录签名，免费接口拿不到。配了 `TIKHUB_API_KEY`（GitHub Secret）后，每天早报那次运行会经 [TikHub](https://tikhub.io) 拉：

- **抖音热点宝·视频热榜**（`src/config.js` 的 `DY_HOT_QUERIES`）：抖音官方的热门视频榜，按标题关键词（AI / 即梦 / 可灵 / 豆包）过滤，时间窗口近 1 / 3 / 7 天，外加「高点赞率」「低粉爆款」两个子榜。每天约 400 条候选。注意榜单上的点赞 / 播放是「这个时间窗口内新增的」，不是累计：累计点赞以详情接口为准，近 24 小时新增点赞用来算飙升，播放标成「近 N 天播放」
- **确认官方 AI 标**：榜单本身不带 AI 标，按点赞从高到低查详情，只留抖音官方标了 AI 的（作者声明 / 平台识别 / AI 特效角标）；标题里明确说「不是 AI」的直接排除。查过的记在 `data/dy-verified.json`，14 天内不再查，所以只有新上榜的才花钱

重点类型：AI音乐、AI MV、AI歌手/艺人、AI鬼畜、AI影视、AI换人。早报里的「抖音高赞榜 / B站高播放榜」是近 30 天所有 AIGC 作品（不限类型）**严格按累计点赞（抖音）/ 播放（B站）取前 10**，同一作者只留最火的一条；AI 只负责写「爆点」「参考」，不参与挑选。

费用：热榜每页 0.001 美元（每天约 15 页），查详情每条 0.001 美元（每天最多 `DY_VERIFY_PER_DAY` = 150 条，AI 标查过就记 14 天；数据会涨，所以先拿 `DY_REFRESH_PER_DAY` = 50 次刷新点赞最高的 AI 视频，剩下约 100 次查新上榜的）。第一天约 0.17 美元，之后每天约 0.05~0.1 美元（每月约 2~3 美元）。余额低于 1 美元时邮件底部提醒，低于 0.1 美元自动暂停。手动推送（`daily-now`）也会拉一次。

## 小红书 AIGC 爆款 + 小红书热点（TikHub，付费）

同样用 `TIKHUB_API_KEY`，每天早报那次运行拉一次，同一天不重复拉（`data/xhs.json` 记着哪天拉过；要强制重拉设环境变量 `XHS_FORCE=1`）：

- **蒲公英·内容广场「小红书热门」榜**（`XHS_SQUARE_QUERIES`）：关键词 AI、近 7 天、只要视频笔记，按点赞排，每个榜只给 Top 100（3 页）。带累计阅读 / 点赞 / 收藏 / 评论、发布时间、作者粉丝。榜单排名按窗口内新增排，数据大约晚一天
- **确认 AI 标**：榜单不带 AI 标，按排名查笔记详情，只留作者声明了「内容含 AI 生成」的（`note_statement`）；标题明确说不是 AI、或者在说「被当成 AI」的不查。查过的记在 `data/xhs-verified.json`，30 天内不再查；每天最多查 `XHS_VERIFY_PER_DAY` = 15 条
- **创作者中心·热点灵感**：小红书自己的热点榜（20 条，带「多少人在看」），放进热梗热搜

小红书爆款进「小红书热点」板块和邮件，同时作为素材喂给抖音 / B站选题（借鉴题材改成原创），没有单独的小红书选题。搜索笔记接口实测不好用（时间筛选不生效、搜出来多是干货帖），没用。

费用：内容广场每页 0.02 美元 × 3，热点榜 0.01 美元，查详情每条 0.01 美元（最多 15 条），每天约 0.1~0.22 美元。

## 花费和省钱机制

- **TikHub**（抖音 + 小红书）：抖音热点宝每天约 21 页 + 查详情最多 150 条，约 0.1~0.17 美元；小红书约 0.1~0.22 美元。合计每天约 0.2~0.4 美元。余额低于 1 美元邮件提醒（按当天两边一共花的钱估还能用几天），低于 0.1 美元自动暂停。
- **DeepSeek**（AI 分析）：每天的 token 用量记在 `data/deepseek-usage.json`。余额低于 3 元（`DEEPSEEK_WARN_BALANCE`）邮件提醒，并按最近的用量估还能用几天。
- **只给会被看到的内容写分析**：视频只给每个平台 24 小时飙升前 80 + 30 天热度前 80 写爆点 / 参考（`ANALYZE_TOP_VIDEOS`），其余只分类；热歌只分析每个榜前 20 首（`ANALYZE_TOP_SONGS`）。哪条之后冲进前 80，下一轮补上分析。
- B站 UP 主粉丝数走免费接口（缓存 7 天）。

## 手动推送（随时发一次）

三种方式，任选：

1. **双击项目文件夹里的 `立即推送.cmd`**（不需要梯子）：重新采集 + AI 分析，跑完立刻发邮件，大约 5~6 分钟。窗口可以直接关，不影响推送。
2. **GitHub 网页**（需要能打开 github.com）：仓库 → Actions → 左侧「AIGC 热点雷达」→ Run workflow → 模式选 `daily-now` → 绿色 Run workflow。
3. **让 Claude 做**。

## 长期授权码（TRIGGER_TOKEN）

**最省事：双击项目文件夹里的「一键设置.cmd」**，它会打开预先填好的网页，一步步告诉你点哪里，长期授权码和下面的准点触发都会自动配好、自动测试。下面是手动做法，留作参考。

`立即推送.cmd` 和下面的「准点触发」都要用一个能触发运行的授权码。部署用的 `GITHUB_TOKEN` 权限大（能改代码、改 Secrets），不适合放进 cron-job.org 这类第三方服务，所以单独生成一个只能触发运行、有效期最长的：

1. 打开 https://github.com/settings/personal-access-tokens/new （需要能打开 github.com）
2. Token name 填 `aigc-radar-trigger`；Expiration 选最长（有 No expiration 就选它，没有就选 Custom 填一年后）
3. Repository access 选 **Only select repositories**，选 `aigc-radar`
4. Permissions → Repository permissions → **Actions** 选 **Read and write**（其它都不用动）
5. Generate token，复制 `github_pat_` 开头那串
6. 用记事本打开项目文件夹里的 `.env`，加一行 `TRIGGER_TOKEN=刚复制的那串`，保存。不要发到聊天里

这个授权码只能触发 / 查看这个仓库的运行，改不了代码、看不到密钥，泄露了最多被人多触发几次运行。

## 准点触发（cron-job.org，免费）

GitHub 自带的定时经常晚 1~4 小时。用 cron-job.org 每天 08:20 准点触发一次，跑完等到 09:00 准点发：

1. 打开 https://console.cron-job.org/signup 用邮箱注册（免费）
2. 右上角 Settings 把时区设成 **Asia/Shanghai**
3. Cronjobs → **Create cronjob**：
   - Title：`AIGC 早报`
   - URL：`https://api.github.com/repos/lxylxylalala1998-droid/aigc-radar/actions/workflows/radar.yml/dispatches`
   - Execution schedule：Every day at **08:20**
   - 打开 **Advanced** 选项卡：
     - Request method：**POST**
     - Headers 加三行：`Authorization` = `Bearer 你的TRIGGER_TOKEN`；`Accept` = `application/vnd.github+json`；`Content-Type` = `application/json`
     - Request body：`{"ref":"main","inputs":{"mode":"daily"}}`
4. 保存后点 **Test run**，返回 **204** 就是成功了（GitHub 那边会多一次运行，今天已经发过的话它只采集，不会重复发邮件）
5. （可选）再建两个，URL 和请求头一样，只改时间和 body：
   - 每天 **09:40**，body 里 `daily` 换成 `check`：早报没发出就给你发报警
   - 每周一 **09:10**，body 里换成 `weekly`：周报准点发

GitHub 自带的定时还留着当兜底，两边谁先跑都行，不会重复发。

## 报警

- 任何一次运行失败，都会给管理员发一封「⚠ 运行失败」的邮件，写清楚是哪一步出的问题（采集 / AI 分析 / 发邮件……）。
- 每天北京 09:40 检查早报发了没有，没发就发「⚠ 今天的早报还没发出」。
- 管理员默认是 `MAIL_TO` 里的第一个地址；想单独指定，在 GitHub Secrets 里加 `ALERT_TO`。

## 发信前自检

每天日报生成后、发邮件前自动检查一遍（`src/check.js`，结果记在 `data/check.json`）：

- **能自动处理的先处理**：邮件超过 95KB 自动改发精简版。
- **修不了的发报警给管理员**（早报照常发）：选题不足 8 个、和前 3 天重复没被去掉、做法里点名了具体平台、速览 / 高赞榜 / 热搜 / 热歌 / 大事件缺内容、AI 分析出错、抖音 / B站 / 微博数据采集失败、余额不足。

选题本身也会跨天去重：前 3 天推过的同一条作品不再占选题位，还在加速的放进「前几天推过 · 还在涨」；标了「已饱和」的排到最后。

## 周报

每周一早上发一封，回顾过去 7 天：一句话总结、**本周建议做的 5 个方向**、上周一直在涨的题材、上周爆款 TOP5、选题复盘（哪类信号推荐的选题后劲足、时效标签准不准）、工具热度、低粉爆款。网页页头「本周周报」可以看最新一期。

## 手动运行的模式

| 模式 | 作用 |
|---|---|
| `collect` | 只采集 + 更新网页，不发邮件 |
| `daily` | 完整早报，等到 09:00 再发（今天发过就只采集） |
| `daily-now` | 完整早报，跑完立刻发（`立即推送.cmd` 用的就是这个） |
| `mail-test` | 不采集，用最近一份日报立刻发一封（测试邮箱配置） |
| `weekly` | 周报（今天发过就跳过） |
| `check` | 检查今天的早报发了没有，没发就报警 |

## 常改的配置

都在 `src/config.js`：

- `SEND_AT`：发信时间（同时要改 `.github/workflows/radar.yml` 里的早报 cron，提前约 40 分钟启动）
- `BILI_KEYWORDS`：B站搜 AI 稿件的关键词；`DY_HOT_QUERIES`：抖音热点宝视频热榜的关键词和时间窗口
- `RSS_FEEDS`：AI 资讯源
- `QQ_TOPS` / `NETEASE_TOPS`：音乐榜单

收件人直接改 GitHub 上的 `MAIL_TO` Secret，不用改代码。

## 本地运行

```bash
npm install
cp .env.example .env      # 填上 DEEPSEEK_API_KEY 等
npm run collect           # 采集
node src/curate.js        # AI 标注 + 日报
npm run build && npm run serve   # 网页预览 http://localhost:8080
node src/mail.js --dry    # 邮件预览 out/mail.html
```

## 目录

```

  sources/       各平台采集器
web/             网页（原生 HTML / CSS / JS）
.github/workflows/radar.yml   定时任务
```
